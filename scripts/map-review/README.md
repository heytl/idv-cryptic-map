# 地图区域审核包

为固定三层地下地图长图生成离线审核页面、像素坐标和待同步资源。工具只读输入资源，不连接远端，也不写入正式配置。

依赖 Python 3、Pillow 和 numpy。使用仓库相对路径指定输出目录：

```powershell
python scripts/map-review/build.py "<资源目录>" .tmp/map-review
```

直接用 Chrome 打开输出的 `index.html`。此文件内嵌原图，可独立离线打开。按文件夹分类、按文件名命名布局。全图和楼层固定原图全宽，入口识别白色边框后向内缩进 8 像素，去掉边框及抗锯齿残留。

## 审核与导出

切换全图、入口和楼层，查看原图边界或放大图片。开始和结束坐标均以原图像素表示，结束坐标不包含该行；矩形仍使用 `{x, y, width, height}`。页面支持重叠区域，不会将楼层强制切为互斥区间。

修改保存在当前浏览器，浏览器或文件来源变化后不会自动共享。审核后导出 JSON 留存；修改区域会自动撤销该布局的审核状态。编辑全图范围前须保证楼层仍在全图内。

修改坐标后，使用导出的 JSON 生成新包：

```powershell
python scripts/map-review/build.py "<资源目录>" .tmp/map-review-approved --coordinates "<导出的坐标JSON>"
```

重建会核对源文件列表、SHA-256 和原始尺寸，并重新裁切资源和计算资源键。页面导出的 JSON 会移除已修改布局的旧资源引用，避免坐标与裁切图片失配。不要把旧包的资源与新坐标混用。

输出包含：

- `index.html`：独立审核页面。
- `coordinates.json`：原图区域、全图相对楼层区域、源文件哈希、分类和审核状态。
- `coordinates.csv`：便于逐行核对的坐标表。
- `assets/maps/`：保持原始分辨率的无损 WebP 全图和入口图。楼层复用全图与区域坐标，不另存重复图片。
- `sync-candidate.json`：内部 V4 格式的资源和楼层区域候选，不是可直接导入的整库配置。

同步时须匹配目标已保存配置中的地图、难度、入口类型、分类和楼层标识；候选 `b1/b2/b3` 代表地下三层，不能默认覆盖目标标识。全图相对坐标为 `原图Y - 全图裁切起点Y`，且 `floorRegions.sourceKey` 必须指向同一张裁切全图。

## 识别范围

识别器针对顶部白色入口框、黄色楼层标题、三张地下地图与底部图例的长图版式。它逐图检测边界，不使用统一裁切坐标。图形颜色阈值及标题搜索窗口是该版式的启发式规则，不适用于任意版式；遇到歧义会报错，不静默套用默认值。

每层独立保留地图内容包络及余量。标题和上一层地图处于相同高度时，优先保证本层地图完整并排除其他层图形，必要时不保留标题。跨楼层的红色虚线路径可能仍出现在区域边缘。自动识别仍须通过原图对照进行人工审核。

验证资源内容与坐标：

```powershell
python scripts/map-review/verify.py "<资源目录>" .tmp/map-review
```
