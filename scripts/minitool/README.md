# 小红书小工具构建

使用当前 Web 源码与正式网站当前公开 V6 数据构建离线小工具。正式网站入口来自共用项目信息；构建前后核对配置哈希，来源不可用或抓取期间配置变化时停止，不回退到旧快照。页面、筛选、楼层裁切、缩放和旋转复用现有组件，线上 Web 构建不受影响。

本地已有 Node.js、Python 3 和项目依赖时运行：

```sh
pnpm build:minitool
```

输出目录为 `dist/minitool/`，ZIP 为 `dist/idv-cryptic-map-minitool.zip`。构建证据、原始公开响应、资源清单与审计摘要位于忽略的 `.tmp/minitool/`。抓取复用 `main` 中已有的静态发布流程，最多并发 6 个下载；只有 URL 与已校验内容哈希一致的不可变图片才可复用本地缓存。

需要其他公开数据源时可显式设置进程环境变量 `MINITOOL_SOURCE_URL`，构建记录会将其标记为自定义来源。只有明确要求冻结 Git 数据时才设置 `MINITOOL_SNAPSHOT_REF`；该模式会标记为 Git 快照，不能当作当前正式数据。构建记录保存真实来源、内容版本、更新时间、抓取时间和配置哈希，地图或布局数量相同不代表内容一致。

适配器将配置随脚本交付，检查全部引用图片的内容哈希，排除历史版本、开发文件、PWA、网络统计与外部导航。偏好优先使用平台 Storage；低版本可降级到不保证持久性的浏览器存储。字体按本次正文、英文标题和布局备注分别子集化，地图图片与楼层裁切坐标保持原样。

默认保留图片原始字节。内容增加导致 ZIP 超过上传门槛时，可以显式设置进程环境变量 `MINITOOL_IMAGE_QUALITY=85`，对包内图片进行等尺寸 WebP 有损重编码；不缩放、不改变裁切坐标，编码后更大的文件继续保留原图。源图留在抓取目录，派生图使用自己的内容哈希命名，`.tmp/minitool/media-profile.json` 记录源图与派生图的哈希、尺寸、字节数及处理结果。审计会重新验证派生结果，并按原始正式响应比较业务配置。该选项只影响小工具包，交付时须明确质量参数及实际包体；图片可读性仍需人工和真机确认。

`audit.mjs` 使用现有 Acorn 依赖按 ES2017 解析最终经典脚本，还原嵌入配置并与抓取响应逐字段比对，再检查禁用能力与资源引用；`package.py` 仅使用标准库，检查路径、文件类型、重复条目、CRC、10 MiB ZIP 与 30 MiB 解压上限。内置数据是抓取时的公开快照，后台更新后需重新构建并发布。

可执行 `node scripts/minitool/verify-browser.mjs` 做现代 Chrome 回归。它仅运行本地静态服务，施加严格 CSP，并提供缺失 API 与旧 CSS 的测试条件；不代表 Chrome 61、平台容器或真机已通过验收。交付前还须按当前开发 Skill 重新获取在线规范，核对能力、高消耗标记与性能自检。

上传前使用相同 ZIP 在创服平台模拟器、Android 真机和 iOS 真机验证。此构建命令不会登录、上传、生成预览或送审。
