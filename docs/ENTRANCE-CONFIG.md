# 按地图与难度配置入口

内部内容继续使用 V3，使用 `entranceRulesVersion: 2` 表示独立难度开关与入口规则；旧的无标记配置及入口能力版本 1 可读取、迁移。新版 Web 与小程序读取公开 V5，旧 V4 接口保留降级数据。

## 数据与迁移

每个 `gameMaps[]` 保存 `entranceRules.hard` 和 `entranceRules.nightmare`，每项包含：

- `allowed`：后台允许录入的入口类型，不可重复。
- `enabled`：选择开放的入口类型，必须属于 `allowed`；顺序即展示顺序，第一项为默认入口。实际对玩家可见还需难度开关开启。

每张地图另有 `modeVisibility: { hard: boolean, nightmare: boolean }`。关闭难度只隐藏公开数据，保留原入口选择、顺序、布局发布标记和图片；全部关闭时整张地图不出现在玩家目录。显示中的难度必须至少选择一个开放入口，隐藏难度允许空列表。

```json
{
  "hard": {
    "allowed": ["side", "front", "upstairs"],
    "enabled": ["side"]
  },
  "nightmare": {
    "allowed": ["front", "upstairs"],
    "enabled": ["front", "upstairs"]
  }
}
```

`normalizeEntranceRules` 只为缺少规则的旧地图补充上述默认值；原有入口引用会并入允许录入集合，以保留历史草稿。显式关闭、已有顺序及已有规则不会被默认值覆盖。规范化不修改布局、ID、资源键、发布标记、内容版本或更新时间，也不会在读取时写入存储；显式保存时沿用版本递增和备份流程。

缺少 `modeVisibility` 时按旧入口列表非空推导显示状态：旧空列表继续隐藏。显式 `false` 不会被回填。后台区分 `configuredEntranceTypes`（后台保留选择）与 `enabledEntranceTypes`（实际公开选择）；隐藏难度仍可以创建并准备布局，重新显示时检查每个选中入口是否有完整发布资料。

现有门型仍为侧门、正门、二楼门。本轮实现可配置这些门型的组合，增加全新门型仍需扩展类型、展示字典和分类逻辑。楼层发布要求、正门通道分类和其他入口方向分类保持原有语义。

## 后台操作

地图管理采用地图列表与当前地图编辑区。桌面直接选择左侧地图，窄屏使用地图下拉选择；右侧集中编辑地图发布、名称、顺序、困难与噩梦配置。新增地图使用独立创建表单，地图名称与地图标识直接显示为同级字段；标识默认自动生成，也可直接修改。新地图默认为草稿，两个难度初始隐藏。

后台交互控件直接使用 Naive UI：`NMenu`、`NSelect`、`NCollapse`、`NTable`、`NCard`、`NForm` 等。自定义样式仅承担页面布局和响应式尺寸，控件外观与交互沿用组件库。

每种入口通过“使用方式”选择：不使用（不允许录入）、仅录入（允许录入但尚未开放）、开放。选择开放自动允许录入；已有布局引用的入口不能直接改为不使用，可以先改为仅录入。多入口时通过“默认入口”选择首项。困难、噩梦各有“前台显示”开关，隐藏后仍能编辑入口选择。高级标识与回收站操作放在次要位置，修改仍统一点击顶部“保存修改”。

新建布局默认创建当前配置选择开放的入口项，也可以添加尚未开放但允许录入的入口；此行为不受难度隐藏影响。未开放入口可以逐步补录，方向或入口图缺失时不公开。新发布布局至少补齐一个选择开放的入口；关闭整个难度可以保留其后台布局。

关闭入口不会删除后台记录、图片和历史统计。若已发布布局因此没有可用入口，该布局仅从公开响应隐藏，仍保留原发布标记。移除“允许录入”时，任何未删除布局仍有该类型引用都会阻止保存，并提示先处理布局。切换布局难度保留原入口资料，不自动清除。

新开放门型时，至少有一个已发布且未删除的布局提供完整资料。下架最后一份资料时需同步关闭入口。历史上已存在的空模式不因迁移被强制重填；新增地图发布、重新上架及新开放入口仍执行完整资料检查。

## 公开接口与兼容边界

- `/maps-v5.json`：地图仅公开 `enabledEntrances`，不公开后台的 `allowed`。布局仅输出已开放且完整的入口；无可用入口的布局不输出，两个难度均关闭的地图不输出。
- `/maps-v4.json`：输出当前开放入口与旧客户端固定入口规则的交集，困难仅能表达侧门，噩梦仅能表达正门、二楼门。不会重新开放已经关闭的入口。旧客户端可能显示空选项，不能获得完整的新组合能力。
- 新 Web 与小程序按当前地图、难度恢复偏好和处理旧链接；入口失效时选择该模式的默认入口，模式关闭时选择同地图的可用模式，全关闭时返回地图目录。地图或模式改变后清理旧筛选条件。
- 统计校验与公开入口判断一致；新开放入口可以记录访问，已关闭或不完整入口拒绝新事件，历史记录保留。
- 旧后台遗漏或仍使用入口能力版本 1 时，保存会返回 `admin_upgrade_required`，防止覆盖独立难度开关。新版写入必须使用版本 2，并为每张地图携带完整入口和难度显示规则。

旧备份通过相同规范化入口恢复；完整导出保留全部后台入口和规则，包括未公开资料。恢复继续保留新增 ID 的墓碑，原有版本冲突检查不变。

Web 配置缓存与离线完成标记升级为 V5，已有图片缓存可复用。升级客户端后应联网加载新版配置并重新确认离线包；关闭入口无法撤回已经下载到设备的旧内容。小程序需重新构建和发布，旧安装包不会自动识别新入口组合。

## 验证与运行

```sh
pnpm test
pnpm check:shared
pnpm check:worker
pnpm build
node deploy/build.mjs
node --test deploy/server.test.mjs
pnpm verify:e2e
pnpm verify:pwa
pnpm verify:pwa:update
```

先按项目 README 启动隔离验收后端，再运行 `node scripts/verify-entrances.mjs`。该检查仅允许本地地址，验证渐进补录、关闭入口、地图隔离、入口顺序、V4 降级、统计、旧后台写保护和备份导出，并在结束时恢复完整原始样例配置。服务端维护的内容版本会正常递增。

本地前后台 dev 验证时，将公开 API 和后台代理临时指向隔离后端。已有本地代理可能连接远程环境，不能直接以其为写入验收目标。仅修改进程环境变量或忽略的本地配置，不把环境信息写入仓库。

配置沿用单次请求，不增加入口接口、图片资源、数据库表或运行时依赖。规则按地图建立索引，全局资料检查和公开序列化按布局与入口线性遍历。发布前应核对实际新版包、配置请求数量、旧客户端降级和离线更新。

先部署支持 V5 的服务端和后台，再更新 Web / 小程序，最后开放新入口组合。回滚客户端前保留升级前备份；新组合不能仅靠旧版代码正确表达，必要时恢复旧规则并重新验证。
