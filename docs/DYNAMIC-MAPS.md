# 动态地图配置（内部 V4 / 公开 V6）

难度和入口由全局字典维护；每张地图分别关联难度，并为每个关联配置楼层、入口录入范围、开放顺序及显示状态。分类不属于入口字典，也没有独立分类字典；在「地图 → 难度 → 入口 → 配置」中填写分类类型和分类值。同一个入口在不同地图、不同难度下可以使用不同分类。地图管理分为地图、难度字典、入口字典、回收站四个列表；属性在居中弹窗编辑。字典新增、编辑、删除，以及地图移入回收站、恢复、删除均直接保存，无需再点击顶部按钮。入口分类随地图配置通过顶部按钮保存；取消分类弹窗不会改变当前草稿。

## 录入与发布

- 可以先建地图，再补充难度、楼层和布局。草稿允许缺图。
- 发布布局要求全图和至少一个完整开放入口。分类可留空，其他楼层有图片或区域才显示。
- 楼层区域使用原图像素矩形；同一楼层不能同时配置区域和独立图片。替换全图时复核已有区域。
- 默认显示全图，楼层顺序由地图与难度的配置决定。新独立楼层图存放在 `maps/layout/floor/<sha256>.webp`，既有资源键不变。
- 新建未发布草稿可以原 ID 修改难度。首次发布后 `modeLocked` 永久为真。历史布局因缺乏发布历史也保守锁定；改变已锁定布局的难度或地图时使用复制功能。
- 切换地图或难度时检查素材引用。即使楼层 ID 相同，名称含义不同也须确认沿用，或移除并重新录入；取消编辑不会改变原布局。
- 字典标识、关联、楼层和入口实例不可重新分配。有引用的记录使用隐藏、停用或软删除。
- 未使用的楼层、难度字典、入口字典及分类选项可在对应行删除。字典行删除直接保存，分类选项和楼层删除需顶部保存。删除保留标识及 `deletedAt`，不出现在录入选项和公开分类中。服务端与后台共用引用计数，检查地图关联、布局、入口实例、楼层图片和裁切区域，含草稿及回收站；分类选项按地图、难度和入口分别计数。存在引用时提示先解除引用，或使用停用、隐藏。全图为固定项，不能删除。
- 地图列表进入配置详情后，以难度标签切换上下文，分别显示楼层与入口表格。楼层也通过弹窗维护属性；地图与难度的标识不作为日常编辑字段。
- 回收站支持恢复和删除，操作成功即保存。删除设置 `purgedAt`，关联难度与布局一并退役，从后台列表和前台移除；不能直接恢复或复用该地图标识，恢复备份也保留删除状态。图片与历史身份记录不做物理清理，统计名称与访问事件继续保留。已从回收站删除的地图不再占用字典的业务引用计数。
- 即时操作只提交已保存基线上的本次改动，不顺带提交其他地图或布局草稿。失败时列表保持原状，字典弹窗保留输入供重试；版本冲突继续按现有规则提示刷新。每次操作只发一次配置保存请求，不按输入字符保存。
- 字典、分类选项、楼层及回收站地图的删除均需二次确认。取消确认不修改数据；字典确认后立即保存，分类选项和楼层继续遵循所属编辑表单的保存方式。

## 升级和备份

仓库中的 `wrangler.jsonc` 是不含真实 AppID、Access 和云资源标识的公开模板。实际 Cloudflare 配置保存在 Git 忽略的根目录 `wrangler.local.jsonc`，使用 `wrangler deploy --config wrangler.local.jsonc`；CI 远程部署也须在运行时从受保护的配置或密钥生成实际配置，不能直接部署占位符。Docker 自托管继续从本地环境文件或密钥管理读取环境配置。

后台使用 `/api/admin/v4/*`，公开客户端使用 `/maps-v6.json`。旧后台接口返回升级错误。配置优先读取 `config:v4:current`；不存在时将旧 V3（或经既有链路转换的 V2）只读转换成 V4。读取不会写入当前配置，首次显式保存才落盘。

地图难度通过 `entranceFilters[入口标识]` 保存 `filterLabel` 和 `filterOptions`，全局入口只保留名称、顺序及状态。旧 V4 入口字典中的分类在读取时复制到各地图难度，彼此不共享可变对象；旧 V6 响应也在客户端边界进行兼容转换。公开 V6 仅输出有完整公开资料的入口及其地图分类，Web 路由和小程序刷新按当前地图、难度读取筛选项。恢复备份按同一范围保留后续新增分类值的标识，不新增请求或数据库表。

首次落盘前保留原始配置到 `backups-v4/v3-baseline.json`。备份列表合并 V3、V4 的版本快照及迁移基线，资源不重传、不物理清理。导出格式版本为 2，导入仍接受版本 1。每日快照写入 `apps/web/src/data/maps-v4.snapshot.json`；旧 V3 快照保留为历史基线。

恢复旧内容前先转换格式，保留此后新增的字典、关联和实例标识，并保持已锁定状态。恢复内容不覆盖访问事件。Cloudflare 与 Docker 的数据源分别升级，不自动同步。

## 兼容与统计

V4、V5 公开接口继续投影可表达的内容。新增难度、新入口以及无法完整表达的有效楼层不会伪装成旧类型。同 ID 但改名或改变分类含义的内容也不投影。

旧正门仅在兼容投影中固定输出南侧方向，通道从当前 `filterValue` 生成；旧侧门和二楼门必须具备兼容的方向分类。V4 保留固定开放规则，V5 支持原入口类型的动态开放列表。没有兼容入口的布局不会输出。

统计表结构和历史事件保持不变，继续记录进入布局详情的次数。服务端按当前持久字典生成名称；后台使用响应的 `label`。停用内容仍可查询，导出包含名称字典。楼层与入口切换不增加访问次数，90 天保留口径不变。

动态文字沿用原有字体栈，新增字符使用缺字回退，不为动态名称全局覆盖字体。楼层切换栏按节点尺寸定位高亮，宽度不足时滚动；配置缓存与离线完成标记升级到 V6，复用既有图片缓存。

## 验证与发布

执行根目录测试、共享包与 Worker 类型检查、三端构建以及 Docker/SQLite 升级测试。浏览器验收使用隔离服务和本地素材，验证动态录入、旧协议投影、统计连续性、区域编辑及 PWA 更新。

正式升级前冻结后台编辑并备份内容、图片与统计。先升级兼容后端，再更新客户端并核对新旧协议，然后显式保存配置。回滚旧代码必须配合经验证的旧配置；不能直接用整库旧备份覆盖升级后新增统计。
