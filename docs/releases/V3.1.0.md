# V3.1.0 Docker 升级清单

发布日期：2026-11-03。状态：正式 Docker 站已升级并通过验收；Cloudflare 备用站与小程序分别发布。产品版本 V3.1.0、内部配置 V3、公开协议 V5 和服务端内容版本分别管理，私有 workspace 包版本不作为产品发布号。

## 更新范围

- 按地图配置困难、噩梦的显示状态及允许录入、开放的入口，保留隐藏资料和历史统计。
- 新客户端读取 `/maps-v5.json`，按实际入口恢复条件和旧分享链接；V4 保留旧固定入口规则的降级数据。
- 后台地图配置调整、楼层区域预览裁切修复、小程序码和反馈入口；Web 与小程序共用更新日志。

## 数据兼容

- 继续使用 `config:v3:current` 和原 SQLite 挂载，不导入开发数据、不重建内容、不执行 V2→V3 迁移脚本。
- 本次无新增 SQL 迁移、数据库表或运行时依赖。旧地图缺少入口规则时只在内存规范化，读取不写库、不递增内容版本、不改图片、ID、发布时间或统计。
- 新后台显式保存时写入 `entranceRulesVersion: 2`、入口规则及 `modeVisibility`，沿用版本冲突保护及配置备份。旧后台提交缺少能力版本或仍为版本 1 时返回 `409 admin_upgrade_required`；关闭旧标签页并重新进入后台。
- V4 只能表达困难侧门及噩梦正门、二楼门。旧小程序和旧离线包不会自动获得新组合；先更新服务端及 Web，另行构建、上传、审核和发布小程序，最后开放新组合。
- Web 配置缓存及离线完成标记更新为 V5，已有图片缓存复用。升级需联网加载新配置并重新确认离线包；已下载的旧内容无法远程撤回。

## 发布顺序

1. 将已验证的 `dev` 合入 `production` 并推送，保留双方历史；确认工作区与目标提交。`production` push 仅验证。
2. 在 GitHub Actions 的 **Release** 中选择 `production` 与 `docker`。该工作流锁定完整 SHA，重新执行应用与 AMD64 / ARM64 容器检查，成功后发布双架构镜像。记录运行链接、完整提交 SHA、镜像摘要及两架构清单；不使用浮动标签部署。
3. 服务器拉取新摘要镜像，拉取失败时保持旧服务。记录升级前镜像摘要、内容版本及 V4 公开地图/布局数量；安排维护窗口，暂停后台编辑。
4. 按 [Docker 指南](../DOCKER.md) 停机并备份 SQLite；备份复制到服务器外，验证文件可读及完整性。保留原密钥、数据挂载、端口和旧镜像。
5. 将本地部署配置的 `APP_IMAGE` 改为新摘要，执行 `docker compose up -d --no-build --pull never app`。健康检查和下述业务验收通过后恢复编辑。
6. 通过验收后记录实际升级时间、镜像摘要、前后内容版本、公开数量、备份校验和及结果；环境信息与备份位置保存在私有运维记录。正式部署确认后再将共用更新日志改为正式发布并重新构建发布，不能提前标记成功。

完整 SHA 标签格式和详细命令见 [Docker 镜像发布](../DOCKER.md#github-镜像发布与服务器手动更新)。此次准备不自动部署 Cloudflare，也不同步两平台内容。

## 验收与性能

- 本地：共享、Worker、Web、后台、小程序测试与类型检查；前后台与小程序预览构建；Node/SQLite 集成测试；入口配置、Chrome E2E、区域预览、PWA 离线及旧缓存升级检查。
- 升级回归：使用已有内容、图片及历史统计的 V4 SQLite 样例启动新版，验证读取不改原始配置；旧后台保存被拒绝，新版保存隐藏难度后重启，布局原始资料、图片、配置备份与历史统计仍在。
- 镜像：CI 必须在原生 AMD64 / ARM64 runner 检查只读根文件系统、非 root、健康、V4/V5 接口、Bearer、表单登录及重建后的会话持久化。没有本地 Docker 时以通过的 CI 为镜像放行依据。
- 正式站：健康为 200，V5 为 JSON 且 `schemaVersion: 5`，V4 为兼容 JSON；无编辑时内容版本与基线不变；公开地图、布局、抽查图片一致。另查后台登录、筛选、旧链接、难度隐藏、离线重下载及统计。
- 浏览器：关闭旧后台页；确认玩家端刷新获得 V5 配置。升级自动更新页面但不刷新后台草稿，旧图片缓存应保留，旧 V4 离线标记不能误报 V5 已下载。
- 性能：普通目录加载保持单次配置请求，不增加逐入口请求或图片预加载；规则索引与序列化保持按布局/入口线性处理，不引入定时轮询。记录构建 JS gzip、PWA 预缓存大小；服务器按相同数据与请求量对比升级前后延迟和内存，不以本地样例替代生产容量结论。

## 回滚

停止编辑，先保存最新数据库与故障日志。未发生新规则写入且内容兼容时可切回旧镜像摘要并验证；已保存新入口规则或难度开关时，不能只凭数据库表结构相同判断旧镜像可用。优先修复新版，必要时停机恢复升级前数据库、清理对应旧 WAL/SHM，并恢复旧镜像和文件权限。

恢复整库会撤回备份之后的内容编辑和访问统计，需保留最新数据库用于后续核对。客户端也可能仍缓存新版，回滚后必须联网验证页面、配置协议和离线行为；仅切换镜像不代表浏览器已回退。不要删除原数据目录、升级备份或旧镜像。
