# 全图区域与移动端编辑器

内部配置仍为 `schemaVersion: 3`，后台接口和 KV 键不变。当前网页统一读取 `/maps-v4.json`；`/maps-v2.json`、`/maps-v3.json` 与 `/api/public/v2/maps` 返回 410 和升级说明。旧页面分享地址继续由原路由解析。

## 内容与迁移

每个布局继续保存 `floorImages.full`。可选 `floorRegions` 结构：

```json
{
  "sourceKey": "maps/layout/full/example.webp",
  "imageWidth": 900,
  "imageHeight": 1500,
  "regions": {
    "floor1": { "x": 0, "y": 0, "width": 900, "height": 700 }
  }
}
```

矩形是相对于最终全图左上角的整数像素；允许重叠，禁止越界、零面积、非整数、未知楼层以及来源不匹配。同一楼层不能同时保存区域与独立图片。全图本身不能配置为区域。困难与噩梦的发布完整性规则保留，草稿可以缺楼层。

不批量猜测历史坐标。后台“选择区域”支持原楼层图对照；确认并完成后，区域替换该层图片引用。其他楼层保留原样。若全图不含某楼层，先保留旧图片，待更新完整全图后再转换。

上传的全图直接保存，已移除自动拼接流程。换图或裁切全图会进入区域复核，已有区域必须逐个确认；全图与确认后的区域仅在上传成功后同时应用到布局草稿。取消或失败均不修改原配置。旧存储图片不会物理删除，历史备份可继续恢复。完整导出只收集当前实际引用的资源，区域随配置保存。

## 操作

- 手机使用全屏编辑器，精调按钮固定可见；横向工具栏可以滚动。桌面在侧栏显示预览与数值。
- 双指始终缩放平移图片；“调整区域”模式拖框移动、拖四角四边改尺寸，框外拖动图片。“移动图片”模式锁定选框。
- 第二根手指加入后结束选框拖动；双指操作结束后，剩余手指不能继续移动选框，需全部抬起重新按下。
- 桌面滚轮以指针为中心缩放，空格拖动图片。编辑区获得焦点后，方向键微调 1 像素，Shift 调整 10 像素。
- 精调支持整体或单边移动及坐标输入；控制点维持 44 CSS 像素点击区域，边界拖动显示局部放大预览。
- 一次拖动对应一步撤销；镜头移动不进入选框历史。切楼层保留本次修改。更改的区域需要再次确认，避免未确认修改被静默丢弃。
- “完成”应用到布局草稿，再点击布局“应用”，最后在后台顶部“保存修改”后正式生效。失败可以直接重试。
- 入口裁剪复用相同编辑器，支持 1:1 锁定，仍输出独立 WebP 和 300px 宽缩略图。

## 发布与回滚

发布顺序为验证、Git 提交、部署。测试环境优先通过 `v3-dev` 推送触发现有 CI；部署记录应关联提交 SHA 与 Worker 版本，不从有未提交改动的工作区部署。2026-10-02 首次预览部署漏掉了提交步骤，后续已补齐源码提交，并重新构建核对前后台产物哈希一致；该记录保留实际操作顺序。

1. 在隔离服务完成上述测试，并在预览环境核对新旧混合内容、导出恢复、手机操作。
2. 正式发布前导出当前完整配置及图片，记录当前 Worker 版本。前后台与 Worker 同次发布，静态镜像和独立客户端同步升级到 V4。
3. 部署后检查 V4 为 200、旧协议为 410、旧分享链接可访问；先转换一张布局，核对全图/区域切换与离线包。
4. 新离线状态使用 V4 标识及数据版本，旧完成标记不沿用；转换或换图发布后需重新下载对应离线包。下载过程中发现配置版本变化会提示刷新，不缓存新配置与旧素材的混合包。
5. 回滚必须使用发布前完整配置配合旧 Worker；旧代码无法解释区域楼层。内部 V3 存储版本并不意味着旧客户端能读取区域配置。不要删除旧资源或备份。
