## 后续操作

日常更新首页运行 `node scripts/static/release.mjs --source-ref origin/production`。新大版本追加 `--archive v4`，将同时生成首页和新的 `/v4/`，已有历史版本不覆盖。版本号支持 `v4`、`v4.1`、`v4.1.0`，沿用正式产品版本编号，不补造未经保留的 V2 历史版本。

GitHub Actions 的 **Prepare static handbook** 只生成经过验证的完整发布包和截图，审核后提交 `main`；不申请长期写入权限，不自动推送。一次性提交 `main` 仍通过正常 Git 发布。

## 上线检查与首次离线刷新修复

初始提交 `0627fbd` 已推送 `main`，Vercel 发布成功，GitHub [静态归档检查](https://github.com/heytl/idv-cryptic-map/actions/runs/40108242706) 通过。线上首页、`/v1/`、`/v3/` 和版本目录均返回 200；无尾斜杠的版本入口正确跳转。对 Vercel 实际响应逐文件读取校验，703 个 UI、配置和资源文件共 44,230,859 字节，与本地验收文件逐字节相同。

线上额外验收发现：Vercel 的 `cleanUrls` 会将预缓存的 `index.html` 跳转为目录地址，缓存响应带有 redirected 标记；首次访问下载离线包后直接断网刷新时，Chrome 拒绝将该响应作为导航页面。本地原静态预览没有这个跳转，因此初始验收未暴露此问题。

修复将离线回退的重定向响应转成普通 HTML 响应，并保留正文、状态和响应头。根页面与 V3 都只修复离线支持脚本、版本清单及文件校验值，地图配置、地图图片、Vue UI 产物和整个 V1 归档均逐字节不变；版本清单记录此次维护。后续正常静态发布仍禁止覆盖历史版本。

本地预览现在模拟 Vercel 的 `index.html` 跳转。浏览器验收去掉了下载前额外在线刷新的步骤，并按具体版本等待 worker 激活。根页面与 `/v3/` 均通过首次访问下载离线包、断网重载目录、断网重载详情与离线切层检查；新增生成后 worker 的回归测试验证重定向响应的正文及 HTML 类型完整保留。

进一步验证版本切换时，修复了归档页面暂由根 worker 控制后、归档 worker 首次接管引发额外刷新的问题。只有当前版本原有 worker 更新才触发页面重载，父级 worker 到新归档的首次接管不重载，避免打断下载；新增回归测试同时验证正常同版本更新仍只重载一次。
